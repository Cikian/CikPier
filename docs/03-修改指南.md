## 〇、动手前的三条铁律

改任何东西之前，先把这三条记住，能省掉大部分返工：

### 铁律 1 · 前端是**三个静态文件**，没有构建步骤

改 `app/frontend/src/` 下的文件**不需要任何编译命令**。
`go:embed` 会在 `wails build` 时把它们打进 exe。

- `wails dev` 下改前端 → 自动刷新
- `tools/build-preview.ps1` 的 `design/preview/` 里是**副本** → **改完必须重跑脚本**

### 铁律 2 · 改 Go 方法后必须重新编译，前端才认得

`call('方法名')` 走的是 Wails 运行时反射。**加/改了 `App` 的导出方法，
必须重启 `wails dev` 或重新 `wails build`**，光刷新页面不行。

### 铁律 3 · 两件事永远不要改坏

| 不能动 | 为什么 |
|---|---|
| `cfgfile.Default()` 里的 `LogTo: "console"` | 界面靠读 frpc 的 **stdout 管道**判断连接状态。写成文件路径 → 管道里读不到东西 → **界面永远停在"正在连接…"**，而 frpc 其实早就连上了 |
| `LoginFailExit: false` | 改成 `true`，开机时网络还没就绪就直接退出且不重试 |

这两条都在 `internal/cfgfile/cfgfile.go` 的 `Default()`（L87–104）里，
源码注释已经写明了原因。历史上这两个都出过真实事故。

## 一、改界面文案

文案分散在三个地方，**先判断你要改的属于哪类**：

| 改什么 | 去哪 |
|---|---|
| 页面标题、卡片标题、表单标签、按钮文字、占位符、空状态提示 | `app/frontend/src/index.html` |
| 提示条（黄/红/蓝）、Toast、确认框内容、动态拼出来的文字 | `app/frontend/src/main.js` |
| **写进 `frpc.toml` 的注释** | `app/internal/cfgfile/cfgfile.go` 的 `Render()` |
| **日志的中文翻译** | `app/internal/frpcman/logparse.go` 的 `rules` 表 |
| **代理错误的中文翻译** | 同文件的 `errorRules` 表 |
| **代理状态的中文**（运行中/启动失败…） | 同文件的 `TranslateStatus()` |
| 诊断页每一条的结论 | `app/app.go` 的 `Diagnose()` |

**操作步骤**（以改按钮文字为例）：

1. 在 `index.html` 里搜到那行文字（中文直接搜就行）
2. 改掉，**不要动 `id` / `class` / `data-*`**
3. `wails dev` 下会自动刷新；只看界面就重跑 `build-preview.ps1`

> ⚠ **在 `main.js` 里拼 HTML 时，所有来自用户的字符串都要过 `esc()`**（L14）。
> 代理名、日志内容这些都是用户可控的，不过转义会出问题。这是现成的工具函数，别自己写。

## 二、改配色 / 间距 / 圆角 / 字体

**只动 `app/frontend/src/main.css` 顶部的 `:root`**（L7–50），别去改具体规则。

| 想改 | 变量 |
|---|---|
| 主色调（按钮、开关、强调） | `--mint-50` … `--mint-700`，然后 `--primary` / `--primary-hover` |
| 页面底色 / 卡片底色 | `--bg` `--surface` |
| 文字深浅四级 | `--fg` `--fg-2` `--fg-3` `--fg-4` |
| 状态色（成功/警告/危险/信息/空闲） | `--ok` `--warn` `--danger` `--info` `--idle`（各带 `-bg` / `-fg` 变体） |
| 间距节奏 | `--s1` … `--s10`（8px 为基准） |
| 圆角 | `--r-sm` … `--r-full` |
| 全局过渡 | `--t` |
| 字体 | `--font`（字体文件在 `assets/fonts/`，是**离线打包**的，不要改成联网字体） |

**换整个主色**的意思就是把 `--mint-*` 那一组换成目标色的色阶，再让
`--primary` 指向新色阶的 500 号。**注意**：`internal/icon/icon.go` 里的
`StateConnected` 也是薄荷绿，换主色时如果想让托盘图标跟着变，
要一起改（见 [`04-换品牌与图标.md`](04-换品牌与图标.md)）。

> ⚠ 改完配色记得跑一次 `build-preview.ps1 -Shots` 出图看效果 ——
> 颜色这种东西只在脑子里推演很容易翻车。

## 四、改窗口标题 / 尺寸

`app/main.go` 的 `wailsOptions()`（L35–72）：

```go
Title:     "CikPier",      // 窗口标题（= 任务栏显示的名字）
Width:     1180,           // 初始宽
Height:    760,            // 初始高
MinWidth:  1040,           // ⚠ 最小宽
MinHeight: 640,            // 最小高
BackgroundColour: &options.RGBA{R: 247, G: 249, B: 251, A: 1},  // 初始化时的底色
```

> ⚠ **`MinWidth` 不要低于 1040。** 代理列表是六列布局，窗口更窄时表头会横向溢出。

同一个文件里还有：

| `OnSecondInstanceLaunch` | 用户双击第二次时要做什么（现在是 `ShowWindow()` 把已有窗口拉到前台） |
| `onStartup` / `OnBeforeClose` / `OnShutdown` | 生命周期钩子，实现在 `app.go` |
| `Bind: []interface{}{a}` | 把 `App` 暴露给前端。**加了新结构体要绑进这里，前端才调得到** |

## 五、加一个全新的页面

**三步，全在前端**（除非新页面要后端数据）。

### 第 1 步：`index.html` 加两个东西

**(a)** 在侧边栏 `<nav class="nav">`（L23 附近）里加一个按钮：

```html
<button class="nav-item" data-page="mypage">
  <span class="nav-icon">…</span><span>我的页面</span>
</button>
```

**(b)** 在 `.content` 里加一个同名的容器：

```html
<div class="page hidden" id="page-mypage">
  …内容…
</div>
```

> ⚠ 规则是死的：`data-page="X"` 必须对应 `id="page-X"`。
> **只有默认页（代理）不带 `hidden`**，其它页都带。

### 第 2 步：`main.js` 两处小改

**(a)** `boot()` 里的白名单（L1992）加上你的页名：

```js
const pages = ['proxies', 'logs', 'settings', 'visitors', 'diagnose', 'about', 'mypage'];
```

这个数组**只是给预览工装认 URL hash 用的**，不影响真实程序。

**(b)** 如果切到这一页时需要刷新数据，去 `bindEvents()`（L1769）里
找导航点击的处理，照着已有的分支加一行。

`showPage()`（L164）**不用改** —— 它靠命名约定自动配对。

### 第 3 步（可选）：要后端数据

在 `app/app.go` 里加一个**首字母大写**的方法：

```go
// GetMyPageData 给「我的页面」提供数据。
func (a *App) GetMyPageData() []SomeStruct {
    // …
}
```

前端这样调：

```js
const data = await call('GetMyPageData');
```

**不需要写任何胶水代码** —— Wails 靠反射自动暴露 `App` 上所有导出方法。

> ⚠ 加完 Go 方法**必须重启 `wails dev` 或重新 `wails build`**，光刷新页面找不到。

## 六、加 / 改一个弹窗

弹窗都是「一个遮罩层 + 里面的卡片」：

```html
<div class="scrim hidden" id="mymodal">
  <div class="modal">
    <div class="modal-head">标题</div>
    <div class="modal-body">…</div>
    <div class="modal-foot">
      <button class="btn btn-ghost" data-close="mymodal">取消</button>
      <button class="btn btn-primary" id="mymodal-ok">确定</button>
    </div>
  </div>
</div>
```

| 机制 | 说明 |
|---|---|
| `openModal('mymodal')` / `closeModal('mymodal')` | `main.js` L137 / L139 |
| `data-close="mymodal"` | 带这个属性的按钮**自动关闭**，不用写 JS |
| 点遮罩空白处 / 按 `Esc` | 也会关（已内置） |
| 确认框 | 用 `confirmDialog(opt)`（L149），返回 Promise |

**加新弹窗要做的**：HTML 写好 → 在 `bindEvents()` 里绑确定按钮 →
（要的话）在 `boot()` 的 `pages` 白名单旁**不用管**，弹窗不参与页面切换。

> 预览工装认的弹窗 hash 是写死在 `tools/build-preview.ps1` 的 `$pages` 数组里的
> （`modal-tcp` `modal-http` `modal-stcp` `wizard` `donate` `panel`）。
> 想预览新弹窗就把它加进去。

## 七、加一个后端方法（供前端调用）

1. 在 `app/app.go`（或 `export.go` / `about.go`）里加导出方法
2. **首字母必须大写**，否则不导出
3. 参数和返回值要能被 JSON 序列化
4. 加完 `wails dev` 重启

方法会自动成为 `window.go.main.App.方法名`，前端用 `call('方法名', 参数…)` 调。

**约定**（沿用现有风格）：

| 前缀 | 含义 | 例子 |
|---|---|---|
| `Get*` | 读一个东西 | `GetState` `GetConfig` `GetSettings` |
| `List*` | 读一个列表 | `ListProxies` `ListVisitors` |
| `Save*` | 建或改 | `SaveProxy` `SaveConfig` `SaveSettings` |
| `Toggle*` | 开关 | `ToggleProxy` `ToggleVisitor` |
| `Delete*` | 删 | `DeleteProxy` `DeleteVisitor` |
| `Open*` | 打开外部东西 | `OpenConfigFolder` `OpenExternal` |

> ⚠ **前端拿到的是 JSON 后的值，不是 Go 的零值语义。**
> 比如 Go 里 `bool` 字段没设 tag 的话前端拿到的是 `false`，
> 而"没填"和"填了 false"在界面上可能含义不同 —— 现有代码里
> 代理的开关字段就踩过这个坑（`v.Enabled` vs JSON tag `enabled`，
> 结果开关永远不变绿）。加字段时**明确写 JSON tag**。

## 八、改代理表单（增删字段 / 按类型显示）

代理弹窗（`index.html` 的 `#proxy-modal`）按类型分成几个块，靠 `data-show-for` 控制显示：

| 块 | `data-show-for` | 说明 |
|---|---|---|
| 代理类型 / 名称 | — | 所有类型都显示 |
| 对外端口 | `tcp,udp` | |
| 子域名 | `http,https` | **放在前面** —— 这是绝大多数人该用的方式 |
| 自定义域名（`.fold`，默认收起） | `http,https,tcpmux` | 展开状态由 `applyType` 控制，见下 |
| 多路复用器 | `tcpmux` | |
| 密钥 / 允许访问的用户 | `stcp,sudp,xtcp` | |
| 高级选项（`.fold`） | — | 里面各项另有自己的 `data-show-for` |

**加一个字段要动三处**：

1. **`index.html`** —— 在对应块里加输入框，起个 `id`
2. **`main.js` `openProxyModal(v)`** —— 编辑时把值填进去
3. **`main.js` `collectProxyDef()`** —— 收集时读出来

### 折叠区（`.fold`）的行为

折叠区的展开状态由 `.open` 类控制，切换逻辑在 `bindFolds()` / `setFoldOpen()`。
除此之外还有两条**自动**规则：

| 规则 | 在哪 | 说明 |
|---|---|---|
| **有内容就展开** | `syncFoldOpen()` | 遍历**全部** `.fold`，扫 `input` 的值、`.switch` 的 `on`、`.chips` 里的 chip。加新字段**不用改它**，自动会被认出来 |
| **必填就强制展开** | `applyType()` 打 `data-foldForceOpen="1"` | 某些类型下折叠区里的字段是必填的（如 **TCPMUX 的自定义域名**），这时必须展开，否则用户填不了 |

> 💡 判断"有没有内容"的公共逻辑在 `foldHasContent(fold)`，
> `syncFoldOpen` 和 `applyType` 都用它。

> ⚠ **给折叠区加字段前先想一件事：这个字段在某个类型下是不是必填？**
> 如果是，就得像 `applyType` 里对 TCPMUX 那样强制展开并改写提示文案
> （`pf-customdomain-note`）。frp 的校验是
> `subdomain 和 customDomains 不能同时为空`，所以 TCPMUX（没有子域名字段）
> 下自定义域名就是必填的。

> ⚠ **别只写 HTML 和 CSS 就以为完事了。** 折叠区曾经就是
> **结构 + 样式齐全、唯独没有切换 `.open` 的 JS** —— 点了毫无反应。
> 加任何带状态切换的控件，确认"结构 / 样式 / **切换逻辑**"三样都齐。

> ⚠ `collectProxyDef()` 的输出结构**必须和 Go 侧、和 frpc 的 Store API 契约一致**。
> 这个契约是嵌套的：`{"name":…,"type":"http","http":{localPort, subdomain}}`，
> 而写进 `frpc.toml` 的 `[[proxies]]` 是**扁平**的。
> 转换由 Go 侧的 `flatToDefinition()` 负责。
> **改了收集逻辑一定要跑集成测试**，否则会出现"界面正常但保存失败"。
> 详见 [`06-测试与排错.md`](06-测试与排错.md)。

`applyType(type)`（L814）和 `applyBackend(mode)`（L827）负责按类型切换显示，
加新类型要在这里加分支。

## 九、改日志翻译

`app/internal/frpcman/logparse.go` 里有几张表：

| 表 | 作用 |
|---|---|
| `rules` | 把 frp 的英文日志匹配成中文摘要 |
| `errorRules` | 代理错误信息的中文翻译 |
| `TranslateStatus()` | 代理状态的中文 |

**加一条翻译**：照着已有条目的格式往表里加一行即可。匹配用的通常是正则或关键字。

> ⚠ **`ParseLine()` 会先剥掉 ANSI 颜色转义再匹配。**
> frp 的 console 日志默认带颜色，**而且输出到管道时照样带**：
> `\x1b[0m\x1b[1;34m2026-09-25 ... [I] [client/service.go:312] try to connect...`
> 不剥的话时间戳不在行首，所有正则失配。改这块别把这个顺序弄反。
> 回归测试：`TestParseStripsANSI`。

## 十、改生成的 `frpc.toml`

两个地方：

| 改什么 | 去哪 |
|---|---|
| **写进去的注释文字** | `internal/cfgfile/cfgfile.go` 的 `Render()`（L269 附近） |
| **默认值** | 同文件的 `Default()`（L87）和顶部的一组 `Default*` 常量 |
| **解析/写回的字段** | 同文件的 `rawFile` 结构体 |
| **store 路径、日志段等固定写法** | `Render()` 里（`store.path` 是**点号写法**，见下方警告） |

> ⚠ **`store.path` 必须写成 `store.path = "..."` 这种点号形式。**
> 写成 `[store]` 表头会把后面所有根级键都吃进 store 表里，
> frpc 启动时报 `json: unknown field "log"`。

> ⚠ **`subDomainHost` 是服务端字段**，写进 `frpc.toml` 会启动失败。
> 服务端不配它的话，subdomain 形式的 HTTP 代理会报 `subdomain is not supported`。

## 十二、改连接诊断

`app/app.go` 的 `Diagnose()` 返回 `[]DiagItem`。
现有检查项（**按这个顺序**，前面挂了就直接 return，不会继续往下查）：

| 检查项 | 说明 |
|---|---|
| 程序文件 | `frpc.exe` 在不在 |
| 配置 | 服务器地址填了没。**令牌只报告状态、不作要求**（见下方警告） |
| frp 进程 | 有没有在跑 |
| 运行架构 | 是不是跑在模拟层里（ARM 机器上装错包） |
| 日志读取 | 能不能读到 frpc 的输出 |
| 服务端连接 | 登录成功没有 |
| 代理 \<名字\> | 逐个检查本机后端端口通不通 |

**加一条检查**：照着已有条目的格式 append 一个 `DiagItem`。
三个字段：`OK`（绿色通过）、`Warn`（黄色警告）、都不设（红色失败），
配 `Name` 和 `Message`（**中文，给用户看的**）。

> ⚠ **令牌不是必填项，别在诊断里把它当"配置不完整"。**
> 服务端可以不配 `auth.token`（无认证服务端），这时客户端也必须留空 ——
> 两边都空时 `GetAuthKey("", ts)` 算出来相同，校验照样通过。
> 所以诊断里只写"已设置 / 未设置（服务端未开启认证）"，用 `tokenState()` 生成。
>
> **同理，这几处都不要把令牌当必填**（历史上全是必填，导致无认证的服务端
> 用户根本用不了）：
>
> | 位置 | 职责 |
> |---|---|
> | `App.readyToStart()` | 只校验 `ServerAddr` |
> | `GetState().Configured` | 只校验 `ServerAddr` |
> | `SaveConfig()` | 不校验令牌；**而且不能把空令牌恢复成旧值** |
> | `main.js` `wizardNext()` | 不拦空令牌 |
> | `main.js` `saveConfigForm()` | 不拦空令牌 |
> | `index.html` | 令牌标签不带 `*`，提示里写明可留空 |
>
> 回归测试：`TestITNoAuthToken`（真的起一个无认证的 frps 连一遍）。

前端渲染在 `main.js` 的 `runDiagnose()`。

## 十五、改开机自启

`app/export.go` L420 起：

```go
runKeyName   = `Software\Microsoft\Windows\CurrentVersion\Run`
runValueName = "CikPier"                      // ← 注册表里的值名
var legacyRunValueNames = []string{"frp客户端"} // ← 历史遗留名，每次读写时顺手清理
```

用的是 **HKCU**（当前用户），所以**不需要管理员权限**。
代价是**登录后才启动**，不适合"开机就要在、不等登录"的场景
（那需要改成计划任务，要管理员）。

> ⚠ **给程序改名时，把旧的 `runValueName` 追加进 `legacyRunValueNames`。**
> 旧名字留下的自启项会指向一个已经不存在的 exe —— 用户看不到任何报错，
> 只会觉得"开机怎么不启动了"。这个函数就是为这件事写的。

## 十六、改默认配置 / 向导

| 想改 | 去哪 |
|---|---|
| 默认服务器端口、Web 管理端口、日志等级、日志保留天数 | `internal/cfgfile/cfgfile.go` 顶部的 `Default*` 常量 |
| 向导的步骤和文案 | `index.html` 的 `#wizard` + `main.js` 的 `paintWizard()` / `wizardNext()` |
| 向导完成后写入什么 | `main.js` 的 `wizardNext()` → 调 Go 的 `SaveConfig` |
| **第 3 步「配置完成」显示哪几条检查** | `main.js` 的 `paintWizardDone(st)` |

> ⚠ **默认端口那类值不要"顺手修正"。** 现有代码对 `ServerPort == 0` 是
> **保留**而不是重置 —— 否则用户只改个名字，就把自己配的 7500 悄悄变成 7000 了。
> 加类似的默认值逻辑时沿用这个原则。

> ⚠ **`paintWizardDone()` 是被 `refreshState()` 反复调用的，不是一次性渲染。**
> 因为它要显示「服务端连接」，而那个状态**只在 frpc 打印出
> `login to server success` 之后才成立** —— 保存配置那一刻必然还没连上。
> 只渲染一次的话，向导会永远停在"正在连接…"（这是修过的真实 bug）。
>
> **往这一步加东西时，记得它每秒左右会被重绘一次**：
> 别在里面放只该执行一次的副作用（比如发请求、弹 toast、改全局状态）。
> 同理，任何"读异步收敛状态并渲染"的新界面，都要挂到 `refreshState` 上，
> 而不是渲染一次就完事。
