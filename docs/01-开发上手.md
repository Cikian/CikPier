# 01 · 开发上手

> 目标读者：**第一次接触这个项目、准备改代码的人**（包括几个月后的你自己）。
> 读完这一篇能把它跑起来；每个环节为什么这么做、出错了怎么办，都写在里面了。

---

## 一、这是个什么东西

**CikPier** 是一个 Windows 桌面程序，给 [frp](https://github.com/fatedier/frp) 套了个图形界面。

| | |
|---|---|
| 语言 | Go 1.25+（后端） + 原生 HTML/CSS/JS（前端） |
| 框架 | [Wails v2](https://wails.io)（Go ↔ WebView2 的桥） |
| 界面渲染 | Windows 自带的 **WebView2**（Edge 内核） |
| 产物 | 单个 `CikPier.exe`（前端资源用 `go:embed` 打进 exe） |

**它不修改也不依赖 frp 的源码。** 底层跑的是**官方原版 `frpc.exe`**，本程序只是：
起它、读它的输出、调它自带的 HTTP 管理接口、按它的格式写 `frpc.toml`。

> 这个决定贯穿整个项目。**升级 frp 只需要替换 `frpc.exe` 一个文件**，
> 不用重新编译本程序。详见 [`README.md`](../README.md) 的「三个关键架构决定」。

## 二、环境准备

### 2.1 需要装什么

| 依赖 | 怎么检查 | 怎么装 |
|---|---|---|
| **Go 1.25 或更高** | `go version` | https://go.dev/dl/ |
| **Wails CLI** | `wails version` | `go install github.com/wailsapp/wails/v2/cmd/wails@latest` |
| **WebView2 Runtime** | 不用查 | Win11 自带；Win10 可能要去微软官网单独装 |
| **Node.js / npm** | — | **不需要**。前端没有构建步骤，别装 |

> ⚠ **Wails CLI 的版本要和 `app/go.mod` 里的 Wails 版本对得上**（当前都是 **v2.16.0**）。
> 版本差太多时，`wails build` 可能报一些和真实原因无关的错。
> 装完先跑 `wails doctor`，它会检查 Go / WebView2 / 环境变量并给出明确结论。

### 2.2 国内网络

Go 模块下载走代理会快很多（本机已有的配置）：

```powershell
go env -w GOPROXY=https://goproxy.cn,direct
```

`wails doctor` 和 `wails build` 都不需要梯子；只有 **arm64 版 `frpc.exe` 缺失时**
打包脚本会去 GitHub Releases 下载（那一步可能需要）。

### 2.3 确认能编译

```powershell
cd D:\Tools\frp_0.71.0\cikpier\app
go build ./...          # 只编译，不产出产物
go vet ./...            # 静态检查
```

两条都安静通过（`go vet` 无输出）就说明环境没问题。

## 三、跑起来

### 3.1 开发模式（日常改代码用这个）

```powershell
cd D:\Tools\frp_0.71.0\cikpier\app
wails dev
```

`wails dev` 会做这些事：

- 编译 Go 后端并启动程序
- **监听 Go 源码**：改了自动重新编译 + 重启
- **监听 `frontend/src`**：改了自动刷新界面（不重启进程）
- 附加 WebView2 开发者工具，窗口里按 **F12** 或右键 → 检查

| 参数 | 用途 |
|---|---|
| `wails dev -browser` | 在系统浏览器里开界面，用浏览器自己的 F12 调试 |
| `wails dev -noreload` | 关掉前端自动刷新（调试"刷新本身有副作用"的问题时用） |

> ⚠ **`wails dev` 之前必须先退出正在运行的 CikPier。**
> 程序带严格单实例锁，第二个实例会被直接 `os.Exit(0)` 干掉。
> 表现是：`wails dev` 编译完、打印一行 `Development mode exited`，看起来像什么都没发生。
> **这是 Wails 的既定行为，不是 bug**（`single_instance.go:53`）。
> 排查"程序一闪就没了"永远先想到单实例锁。

### 3.2 不启动程序，只改界面

改纯样式/文案时，用不着真跑程序：

```powershell
cd D:\Tools\frp_0.71.0\cikpier
powershell -ExecutionPolicy Bypass -File tools\build-preview.ps1
```

它会：

1. 把 `app/frontend/src` 的三个文件同步到 `design/preview/`
2. 生成 `preview.html`（在 `main.js` 之前插入了 `mock.js` —— 一个假后端）
3. 用浏览器打开 `design/preview/preview.html` 就能看到完整界面

加了 `-Shots` 还会用 Edge 无头模式把每一页截成 PNG，存到 `design/screenshots/`。

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-preview.ps1 -Shots
```

单看某一页：`design/preview/preview.html#about`，可用的 hash 有
`proxies` `logs` `settings` `visitors` `diagnose` `about`
`modal-tcp` `modal-http` `modal-stcp` `wizard` `donate` `panel`。

假后端在 `design/preview/mock.js` —— 它是**手工维护**的独立文件
（`build-preview.ps1` 不会覆盖它）。界面调到的每个 Go 方法都得在这里有一个对应实现，
否则会看到「**后端不支持的操作：xxx**」。加 Go 方法之后记得也往 mock 里补一个。

> `#wizard` 进去是**第 1 步**。想验第 2、3 步（比如「令牌留空能不能继续」），
> 用一个几行的 driver 脚本自动点 `wz-next`，再配合
> `msedge --headless=new --virtual-time-budget=9000 --screenshot=...` 截图即可 ——
> **时序类的 bug 只能这么验**，光看代码推不出来。

**这个办法的两个好处**：不占用 frp 的管理端口、不会拉起 `frpc.exe`，
所以**正式程序可以同时开着**，边跑边改界面。

> ⚠ **改完 `frontend/src` 一定要重新跑一次 `build-preview.ps1`。**
> `design/preview/` 里那三个文件是**副本**，不会自动跟着变。
> 忘了跑就会出现"我明明改了怎么截图没变"。

> ⚠ **不要用 `PrintWindow` 之类的 API 去截真实窗口。**
> WebView2 走 DirectComposition，抓到的经常是残缺的帧，
> 会让人误以为是布局 bug（为此白查过一轮）。用上面的无头截图。

### 3.3 想看 stderr / 排查启动问题

生产构建是 `windowsgui` 子系统，**看不到任何控制台输出**。想看到：

```powershell
cd D:\Tools\frp_0.71.0\cikpier\app
go build -tags production -o debug.exe .
$env:FRPCGUI_DEBUG='1'
.\debug.exe
```

| 环境变量 | 作用 |
|---|---|
| `FRPCGUI_DEBUG=1` | 把关键节点写进 exe 同目录的 `gui-debug.log` |
| `FRPCGUI_NOTRAY=1` | 完全禁用托盘（用来隔离"是不是托盘导致的退出"） |

> ⚠ **`go build` 不加 `-tags production` 会得到一个什么都不做的空壳程序。**
> 在 `wails/v2/internal/app/app_default_windows.go` 里，没有 `production` 标签时
> `App.Run()` 直接 `return nil` —— 程序 3 秒后静默退出，**退出码 0**，非常难查。
> 永远用 `wails build`，或者像上面这样明确带上 `-tags production`。

## 四、改完代码之后

### 4.1 最小自查（每次改完都跑）

```powershell
cd D:\Tools\frp_0.71.0\cikpier\app
go vet ./...
go test ./... -count=1
```

单元测试**不需要网络、不需要 frp**，几秒钟出结果。

### 4.2 改动涉及 frp 交互时，再跑端到端测试

```powershell
$env:FRPCGUI_BIN='D:\Tools\frp_0.71.0\frp-bins\win-amd64'
go test -run TestIT -v -timeout 400s .
```

它会在本机真的起一个 `frps` + 一个 `frpc`，走完一整条链路。
**为什么必须做**：界面用的「Store API + 嵌套类型块」这套结构如果写错，
界面看上去一切正常，**只是保存会失败** —— 只有对着真 frpc 跑一遍才能确认契约正确。
详见 [`06-测试与排错.md`](06-测试与排错.md)。

### 4.3 要出包了

```powershell
cd D:\Tools\frp_0.71.0\cikpier
powershell -ExecutionPolicy Bypass -File tools\package.ps1 -Version 1.0.0
```

详见 [`05-打包与发布.md`](05-打包与发布.md)。

## 六、常见环境问题

**`wails: command not found`**
`go install` 装出来的东西在 `$(go env GOPATH)\bin`。确认这个目录在 `PATH` 里，
或者直接用全路径 `& "$(go env GOPATH)\bin\wails.exe" build`。

**`wails dev` 编译完什么都没发生**
十有八九是**已经有一个 CikPier 在跑**（单实例锁）。全部退出再试。
任务管理器里找 `CikPier.exe`；托盘图标右键也能退出。

**界面白屏 / 一片空白**
WebView2 没装或版本太旧。跑 `wails doctor` 看它怎么说；Win10 需要单独安装
WebView2 Runtime。开发模式下按 F12 看控制台报错。

**改了 `main.go` 但窗口标题没变**
`wails dev` 对 Go 改动是**重新编译 + 重启**，但如果旧进程没退干净会连不上。
彻底退出后重跑。

**`go test ./...` 里集成测试被跳过**
正常 —— 没设 `FRPCGUI_BIN` 时 `TestIT*` 会 `t.Skip`，这是刻意设计的，
保证 `go test ./...` 在没有 frp 的机器上也能跑。
