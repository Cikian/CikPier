# 06 · 测试与排错

> 目标读者：**改动之后要确认没搞坏东西的人**，以及**东西坏了要查原因的人**。

## 一、测试体系：三层

| 层 | 怎么跑 | 需要什么 | 耗时 |
|---|---|---|---|
| **单元测试** | `go test ./... -count=1` | 什么都不需要 | 几秒 |
| **端到端集成测试** | 设 `FRPCGUI_BIN` 后 `go test -run TestIT` | 真的起 `frps` + `frpc` | 约 20 秒 |
| **界面截图回归** | `tools/build-preview.ps1 -Shots` | Edge（无头） | 约 1 分钟 |

**日常改代码跑第一层就够了。** 碰了 frp 交互（Store、配置、日志）必须跑第二层。

## 三、端到端集成测试

### 怎么跑

```powershell
cd D:\Tools\frp_0.71.0\cikpier\app
$env:FRPCGUI_BIN='D:\Tools\frp_0.71.0\frp-bins\win-amd64'   # 指向含 frps.exe / frpc.exe 的目录
go test -run TestIT -v -timeout 400s .
```

`FRPCGUI_BIN` **没设时这几个测试会自动 `t.Skip`** —— 这是刻意设计的，
保证 `go test ./...` 在没有 frp 的机器上（比如 CI）也能跑通。

### 覆盖了什么

**`TestITAppLifecycle`** —— 主链路，走一整套：

1. 识别出 `frpc.toml` 里的静态代理
2. 新建 TCP 代理 / 新建 HTTP 代理
3. 确认代理上线
4. 单独启停某一条代理
5. 编辑代理
6. 访问者增删改
7. 跑连接诊断
8. 把手写代理迁移进 Store
9. 删除代理
10. 配置读写
11. 日志解析

**`TestITRecoversFromFileLogTarget`** —— **先复现故障，再验证自愈**：

模拟"用户拿来一份 `log.to = frpc.log` 的配置"（症状：界面永远停在"正在连接…"，
但点开 `frpc.log` 发现其实早就连上了），然后验证：

- 程序能检测到这个坏配置
- 修正后留下 `frpc.toml.bak` 备份
- 修正之后界面能读到日志

**`TestITNoAuthToken`** —— 验证「服务端没有开启认证」这条路径：

起一个**完全不配 `auth` 的 frps**，客户端用**空令牌**去连，然后断言：

1. 空令牌被视为"已配置"（`readyToStart()` / `GetState().Configured` 都为 true）
2. **真的能连上**（`waitState(StateConnected)`）—— 两边都空时
   `GetAuthKey("", ts)` 相同，校验通过
3. 令牌能被**清空**（曾经会被 `SaveConfig` 恢复成旧值，导致永远清不掉）

> 这条路径的每个环节（向导、SaveConfig 校验、诊断页、配置状态判定）
> 以前都要求令牌非空，所以**无认证服务端的用户根本用不了**。

**`TestITManagerCapturesOutput`** —— 验证能真的抓到 `frpc` 的 stdout。

**`TestITHiddenFrpcStillReportsVersion`** —— 验证**隐藏控制台窗口之后仍然读得到输出**。

`HideConsole` 会给子进程加 `CREATE_NO_WINDOW`。要确认这样起进程还能从 stdout
读到 `frpc -v` 的版本号 —— 读不到的话「关于」页会一直显示写死的兜底版本号，
而且几乎不可能联想到是"隐藏窗口"造成的。

> `cmd.Output()` 拿到的是**管道**，理论上跟子进程有没有控制台无关。
> 但"理论上"不够，所以拿真的 frpc.exe 跑一遍。

### 为什么这层不能省

界面用的「**Store API + 嵌套类型块**」这套结构如果写错，
**界面看上去一切正常，只是保存会失败** —— 或者保存出错误的代理。

这类 bug 单元测试抓不到（它不碰真的 frpc），界面也不会报错。
**只有对着真 frpc 跑一遍才能确认契约是对的。**

具体来说，这个契约有个反直觉的地方：

| 位置 | 结构 |
|---|---|
| `frpc.toml` 的 `[[proxies]]` | **扁平**：`{name, type, localPort, subdomain, …}` |
| Store API（HTTP 请求体） | **嵌套**：`{"name":…, "type":"http", "http":{localPort, subdomain}}` |
| Store 的 JSON 文件 | **又是扁平**（`TypedProxyConfig.MarshalJSON` 直接序列化类型块） |

转换由 `flatToDefinition()` 负责。不转换会报
`exactly one proxy type block is required`。

### 已知的不稳定

集成测试偶发失败过一次（`FAIL frpcgui 11.979s`），重跑 3 次都通过，
怀疑是**端口 TIME_WAIT**。遇到偶发失败先：

```powershell
go test -run TestIT -count=1 -v -timeout 400s .
```

还是失败再看具体是哪个断言。

## 五、调试工具箱

### 5.1 环境变量

| 变量 | 作用 | 用在哪 |
|---|---|---|
| `FRPCGUI_DEBUG=1` | 把关键节点写进 exe 同目录的 `gui-debug.log` | 排查启动 / 生命周期问题 |
| `FRPCGUI_NOTRAY=1` | **完全禁用托盘** | 隔离"是不是托盘把程序搞挂了" |
| `FRPCGUI_BIN=<目录>` | 告诉集成测试去哪找 `frpc.exe` / `frps.exe` | 只给测试用 |

用的方式：

```powershell
cd D:\Tools\frp_0.71.0\cikpier\app
go build -tags production -o debug.exe .     # ⚠ 必须带 -tags production
$env:FRPCGUI_DEBUG='1'
$env:FRPCGUI_NOTRAY='1'                      # 需要时
.\debug.exe
```

> ⚠ **`go build` 不加 `-tags production` 会得到一个空壳程序** ——
> 3 秒后静默退出、**退出码 0**，非常难查。原因见 `01-开发上手.md` §3.3。

### 5.2 界面里的「连接诊断」页

用户能自助，开发者更应该先看它。`app/app.go` 的 `Diagnose()`（L853）依次检查：

| 检查项 | 说明 |
|---|---|
| 程序文件 | `frpc.exe` 在不在 |
| 配置 | 服务器地址、令牌填了没 |
| frp 进程 | 有没有在跑 |
| 运行架构 | **是不是跑在模拟层里**（ARM 机器装错包） |
| 日志读取 | 能不能读到 frpc 的输出 |
| 服务端连接 | 登录成功没有 |
| 代理 \<名字\> | 逐个检查本机后端端口通不通 |

### 5.3 手动读 PE 架构

怀疑包/二进制架构不对时：

```powershell
$f='D:\Tools\frp_0.71.0\frp-bins\win-arm64\frpc.exe'
$b=[IO.File]::ReadAllBytes($f); $pe=[BitConverter]::ToInt32($b,0x3C)
'{0:X4}' -f [BitConverter]::ToUInt16($b,$pe+4)
# 014C=x86  8664=amd64  AA64=arm64
```

### 5.4 看 zip 里到底有什么（发布前必做）

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z=[System.IO.Compression.ZipFile]::OpenRead('D:\Tools\frp_0.71.0\release\CikPier-v1.0.0-amd64.zip')
$z.Entries | ForEach-Object { $_.Name }
$z.Dispose()
```

## 六、排错手册

### 程序双击后一闪而过 / `wails dev` 编译完什么都没发生

**先想到单实例锁。** 程序带严格单实例锁，第二个实例会被直接 `os.Exit(0)`：

- 检查任务管理器里有没有残留的 `CikPier.exe`
- 检查有没有一个已经最小化到托盘的实例
- `wails dev` 的输出里会有一行 `Development mode exited` —— 就是这个

**这是 Wails 的既定行为，不是 bug**（`internal/frontend/desktop/windows/single_instance.go:53`）。
`OnStartup` 根本不会被执行，所以在 `startup` 里打的调试日志也看不到。

### 界面白屏 / 一片空白

1. **WebView2 没装或太旧** → 跑 `wails doctor`
2. 开发模式下按 **F12** 看控制台报错
3. 如果是**打包后**的 exe：确认前端资源真的嵌进去了
   （`main.go` 里有 `//go:embed all:frontend/src`；删掉这个注释就白屏）
4. 用浏览器直接打开 `app/frontend/src/index.html` 会显示"后端未就绪" ——
   **这是正常的**（`boot()` 里专门处理了这种情况），不要当成 bug

### 一直卡在"正在连接…"

**按这个顺序查**：

1. **看「连接诊断」页** —— 它会直接指出是哪个环节
2. **`log.to` 是不是 `console`？** —— 这是最隐蔽的死因。
   界面靠读 frpc 的 **stdout 管道**判断连接状态
   （frp 的管理接口根本没有"是否已连上服务端"这个信息）。
   如果 `log.to` 指向文件，管道里读不到东西 → 状态永远不变 →
   界面永远显示"正在连接…"，**而 frpc 其实早就连上了**。
   界面上有「修正并重启 frp」按钮（`fixLogTarget`）。
3. 服务器地址/端口填错、Token 不匹配、防火墙拦了控制端口

> 相关的三道防线：`Default()` 和 `SaveConfig()` 都强制 `console`；
> 启动时 `fixLogTarget()` 自愈并告知用户；界面上 `noLogs` 提示条直接点破原因。

### 向导第 3 步一直停在"正在连接…"（但主界面显示已连接）

**已经修过，回来查说明是别的回归。** 记录一下症状和病根：

- 症状：走完首次配置向导，最后一步「服务端连接」永远显示 ⚠ 正在连接…，
  但点「开始使用」进主界面，顶栏是 🟢 已连接到服务端
- 病根：那个页面原来是在保存配置后**只渲染一次**就写死了。
  而保存那一刻 frpc 还没打印 `login to server success`（状态是从日志推断的），
  于是永远定格在"正在连接"
- 正确做法：渲染函数 `paintWizardDone(st)` 挂在 `refreshState()` 末尾，
  状态一变（含后端推的 `frp:state`）就重绘

排查时先确认这条钩子还在：

```js
// main.js 的 refreshState() 末尾
if (wzStep === 3 && !$('wizard').classList.contains('hidden')) paintWizardDone(S.state);
```

界面留档：`design/screenshots/shot-wizard-connecting.png`（t≈3.5s，正在连接）
和 `shot-wizard-done.png`（t≈9s，已连接）。

> ⚠ 顺带说一下**怎么验这类"时序"bug**：光看代码推不出来，要造一个
> "状态会变"的环境跑一遍。做法是拿 `design/preview/mock.js` 当底子，
> 覆盖 `GetState` 让它的状态过几秒从 `starting` 翻成 `connected`，
> 再用 driver 脚本自动点完前两步，**之后不再点任何东西**，
> 然后分别在 t≈3.5s 和 t≈9s 截两张图对比（Edge 无头 +
> `--virtual-time-budget`）。两张图不一样，就说明它在自己更新。

### 打开「关于」页时闪过一个黑窗口，然后内容才出来

**已经修过，回来查说明是新的调用点又漏了。**

- 黑窗口：有地方用 `exec.Command` 起了 `frpc.exe` 却没隐藏控制台。
  `frpc.exe` 是控制台程序，从 windowsgui 程序里起它会新分配一个控制台窗口
- "内容才出来"：同一个根因 —— `GetAboutInfo()` 阻塞在等 `frpc.exe -v` 返回

排查方法：搜所有起 frpc 的地方，确认每个都调了 `frpcman.HideConsole`：

```powershell
cd cikpier\app
Select-String -Path *.go,internal\*\*.go -Pattern 'exec\.Command'
# 每个结果附近都应该有 HideConsole(...)
```

目前的两处：`frpcman.Manager.Start()`（长驻进程）和 `about.go` 的 `frpVersion()`（一次性）。

> 💡 **这是"漏一处就露馅"的典型**：`Manager.Start()` 早就写对了，
> 所以只有「关于」页会闪 —— 别的地方都正常，很容易以为是自己看错了。

### 提示"找不到 frpc.exe"

`frpc.exe` 必须和 `CikPier.exe` **在同一个文件夹**。

- 程序找的是**自己所在目录**（`os.Executable()` 的目录），不是当前工作目录
- 用户自己换了 `frpc.exe` 时，**必须是同架构的**

### 代理保存失败 / 保存出来是错的

**几乎都是 Store API 的契约问题。** 见 §三 的结构对照表。

- 检查 `collectProxyDef()`（`main.js` L954）的输出结构
- 检查 Go 侧的 `flatToDefinition()` 转换
- **跑集成测试**：`TestITAppLifecycle` 会覆盖这条链路

### 代理开关点了不变绿

**JSON tag 问题。** 历史上踩过：Go 侧字段 `Enabled` 没写 JSON tag，
前端读的是 `v.enabled`，两边对不上，开关就永远不变色。

加字段时**明确写 JSON tag**：

```go
Enabled bool `json:"enabled"`
```

### 日志页空的

三种可能：

1. `log.to` 不是 `console`（见上）
2. frp 进程根本没起来
3. 日志缓冲被暂停了（界面上有「暂停刷新」，检查一下）

### 提示"检测到本机已有另一个 frp 进程在运行"

管理端口上已经有一个 frpc 在跑，但**不是本程序启动的** ——
可能是上次异常退出留下的，或者你另外配了开机启动。

界面上的按钮（`StopExternalFrp`）可以把它停掉。
**注意**：停之前先确认那个进程确实是你自己的，别停掉别人的服务。

### 开机自启不生效

- 用的是 **HKCU** 的 Run 项，所以是**登录后**才启动，不是开机就启动
- 检查注册表：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下
  有没有名为 `CikPier` 的值
- 如果**改过程序名**：旧名字那条自启项会指向不存在的 exe，
  程序每次读写自启设置时会自动清理（`purgeLegacy`）

### 换了程序名之后旧名字还露出来

对照 [`04-换品牌与图标.md`](04-换品牌与图标.md) §二 的 12 项清单逐条核对。
最常见的漏项是：托盘提示（`tray.go`）、写进 `frpc.toml` 的注释（`cfgfile.go`）、
exe 文件属性（`wails.json` 的 `info` 段）。

### 改了 `frontend/src` 但预览截图没变

**忘了重跑 `build-preview.ps1`。** `design/preview/` 里是副本。

### 图标改了但 exe 上没变

**忘了重新 `wails build`。** 图标是在构建时嵌进 exe 的，
`go run ./cmd/genicon` 只写 `build/` 下的文件。

### 打包相关的报错

见 [`05-打包与发布.md`](05-打包与发布.md) §十一。

## 七、写新测试的约定

1. **测试文件放同目录**，命名 `<被测文件>_test.go`，包名用 `_test` 或同包（现有都是同包）
2. **回归测试要写清楚它守的是什么事故** —— 看 `TestDefaultUsesConsoleLog`
   和 `TestITRecoversFromFileLogTarget` 的注释，它们都写明了"曾经出过什么事"。
   这比测试名本身有价值得多
3. **端到端测试统一用 `TestIT` 前缀**，并且开头就检查 `FRPCGUI_BIN`，
   没设就 `t.Skip`
4. **不要为了通过而改测试** —— 带 ⭐ 的那些都是真实事故的回归测试

## 八、已知限制（不是 bug，别去"修"）

| 限制 | 原因 |
|---|---|
| **访问者没有运行态** | `/api/status` 只返回代理、不含访问者。所以界面只显示"已启用/已停用"，**不假装知道它连上没有** |
| **端口预检只探 `127.0.0.1`** | 服务只监听 `::1` 或具体网卡地址时会误报"没监听"。所以**只作提示、不阻止保存** |
| **开机自启是登录后启动** | 用 HKCU Run 项的代价（好处是不需要管理员）。要"开机就在"得改计划任务，要管理员 |
| **托盘里改开机自启后界面不实时同步** | 切到设置页会重新读一次 |
| **http/https 的对外地址不显示端口** | frp 报上来的是"域名 + 服务端内部 vhost 端口"，那个端口通常由 nginx 反代且被防火墙挡着。用户照着加端口必然访问失败（实测：域名 200、加端口超时）。所以只显示域名，端口和解释放进悬停提示 |
| **ARM64 包没在真机验证过** | 手上没有 ARM64 设备 |
