## 三、图标是"算"出来的，不是图片文件

这是本项目最特别的一个设计，改图标前必须理解。

**没有 `icon.png` 这样的源文件。** `internal/icon/icon.go` 用**归一化坐标**
（0..1 之间）定义了图形的几何，然后：

- 任意尺寸都按同一套坐标**重新光栅化** → 16px 和 256px 是同一个图形，不会走样
- 光栅化时开 **4× 超采样**（`supersample = 4`）→ 小尺寸边缘不发毛
- 最后按 ICO 格式自己打包（`ICO()` / `ICOFor()`）

好处：**改一次几何定义，整套尺寸自动重算**，不用手工维护一堆图片。

### 3.1 几何定义（`icon.go` L68–74）

```go
const (
	tileRadius = 0.22   // 底板圆角半径
	splitGap   = 0.085  // 斜缝的半宽
)
```

图形是**一块圆角方形底板 + 一条对角斜缝**：斜缝把底板分成右上、左下两块，
填不同的渐变色。

判据是 `x - y`：

| 区域 | 条件 | 颜色 |
|---|---|---|
| 右上块 | `y < x - splitGap` | 暖色（琥珀 → 橙） |
| 斜缝 | 中间 | 露出底板色（藏青） |
| 左下块 | `y > x + splitGap` | 冷色（亮蓝 → 蓝） |

> 💡 这个图形的含义：**一条通路穿过屏障**，两端连起来 —— 正好是 frp 在做的事
> （把本机的服务"穿透"到外面）。截图见 `design/screenshots/`。

### 3.2 配色（`icon.go` L33–40）

```go
var Brand = Scheme{
	TileTop:    RGB{0x1E, 0x40, 0x72}, // 藏青（底板顶）
	TileBottom: RGB{0x10, 0x22, 0x3F}, // 更深（底板底）
	WarmTop:    RGB{0xFB, 0xB0, 0x3B}, // 琥珀（右上块顶）
	WarmBottom: RGB{0xF5, 0x82, 0x1F}, // 橙（右上块底）
	CoolTop:    RGB{0x59, 0xA9, 0xE6}, // 亮蓝（左下块顶）
	CoolBottom: RGB{0x1B, 0x75, 0xBC}, // 蓝（左下块底）
}
```

三组渐变都是**竖直方向、按整块底板的高度铺开**（不是各自铺各自那一半）。

### 3.3 标准尺寸

```go
var StandardSizes = []int{16, 32, 48, 64, 128, 256}
```

Windows 会按场合挑：任务栏约 32px、资源管理器小图标 16px、大图标 256px。

## 四、换图标：三种改法

### 改法 A · 只换颜色（最常见）

改 `icon.go` 的 `Brand`（L33–40），重新生成即可。

**注意要和界面主题协调** —— 界面主色是薄荷绿 `#10B981`
（`main.css` 的 `--mint-500`）。当前图标用的是橙+蓝（来自作者的个人标识），
如果你想让图标和界面统一，可以把冷暖两半换成薄荷绿的深浅两级。

### 改法 B · 换几何形状

改 `tileRadius`（圆角大小）或 `splitGap`（斜缝宽度），
或者去改 `inTile()` / `Render()` 里判断区域的逻辑（换个分割方向、换成分割曲线）。

```powershell
cd app
go run ./cmd/genicon -preview "$env:TEMP\p.png"
```

`-preview` 会输出一张**对比图**：16 / 24 / 32 / 48 / 64 / 128 六个尺寸
各放大 4 倍并排画，下面再贴一行原尺寸的，方便判断"小尺寸下还认不认得出来"。

> ⚠ **`splitGap` 别调太小。** 缝太窄在 16px 下会糊成一条，两块颜色就贴一起了。
> 现在是 0.085，16px 下约 1.36 像素 —— 基本是下限。
>
> ⚠ **改完一定要看 `-preview` 那张对比图**，别只在脑子里推演。

### 改法 C · 彻底换一个图形

重写 `icon.go` 的几何部分。要保留的接口：

| 函数 | 签名 | 被谁用 |
|---|---|---|
| `Render(size int, s Scheme) *image.RGBA` | 渲染指定尺寸 | `genicon`、`trayicon` |
| `PNG(img *image.RGBA) ([]byte, error)` | 编码 PNG | `genicon` |
| `ICOFor(s Scheme, sizes ...int) []byte` | 打指定尺寸的 ICO | `trayicon` |
| `AppICO() []byte` | 按 `StandardSizes` 打程序图标 | `genicon` |
| `StateScheme(base RGB) Scheme` | 由状态色生成配色 | `trayicon` |

**想先看几版候选**：`cmd/logolab` 是个并排渲染的试验台。

```powershell
cd app
go run ./cmd/logolab -out "$env:TEMP\candidates.png"
```

### 生成之后

```powershell
cd D:\Tools\frp_0.71.0\cikpier\app
go run ./cmd/genicon
```

会写两个文件：

| 文件 | 用途 |
|---|---|
| `build/windows/icon.ico` | **嵌进 exe** + 窗口左上角图标 |
| `build/appicon.png` | 1024×1024，Wails 在非 Windows 平台用，也当备用 |

> ⚠ **生成完必须重新 `wails build`** —— 图标是在构建时嵌进 exe 的，
> 光跑 `genicon` 不影响正在用的 exe。
>
> ⚠ 编译到一半的 exe 如果正在运行，`wails build -clean` 会失败并报
> `Access is denied`。`tools/package.ps1` 会自动清理占用进程，手动 `wails build` 就要自己先退出程序。

## 五、⚠ `logo.svg` 必须跟着改（最容易漏）

`app/frontend/src/assets/images/logo.svg` 是**界面上**用的 logo
（侧边栏 + 关于页水印）。它**不是**从 `icon.go` 导出的，
而是**照同一套数学手写**的 SVG。

**所以改了图标几何，必须同步改它**，否则侧边栏的 logo 和 exe 图标会长得不一样。

### 对应关系

SVG 的 `viewBox` 是 `0 0 64 64`，所以归一化值 × 64：

| `icon.go` 的常量 | 归一化值 | SVG 里的值 | 在哪 |
|---|---|---|---|
| `tileRadius` | 0.22 | **14.08** | `<rect ... rx="14.08">`（L20） |
| `splitGap` | 0.085 | **5.44** | 两个 `polygon` 的顶点（L38–39） |

### 两个三角形的顶点是怎么来的

斜缝两条边界线是 `y = x ± splitGap`。换算到 64 画布：

| 区域 | 不等式 | 三角形顶点 |
|---|---|---|
| 暖色（右上） | `y < x − 5.44` | `(5.44,0) (64,0) (64,58.56)` |
| 冷色（左下） | `y > x + 5.44` | `(0,5.44) (0,64) (58.56,64)` |

> `58.56 = 64 − 5.44`。中间那条斜缝**不画**，直接露出底板色。

### 渐变也一一对应

| SVG 渐变 id | 用在哪 | 起点 / 终点色 |
|---|---|---|
| `ckTile` | 底板 `<rect>` | `#1E4072` → `#10223F` |
| `ckWarm` | 右上 `<polygon>` | `#FBB03B` → `#F5821F` |
| `ckCool` | 左下 `<polygon>` | `#59A9E6` → `#1B75BC` |

三组都是 `gradientUnits="userSpaceOnUse"` 且 `y1=0 y2=64` ——
**按整块底板的高度铺开**，和 `icon.go` 里 `gradient()` 的行为一致。
不要改成 `objectBoundingBox`（那会按各自那一半的高度铺，颜色就对不上了）。

> ⚠ **历史教训**：第一版 `logo.svg` 是凭感觉写了两组六边形顶点，
> 结果两个色块直接贴在一起、**斜缝整个没了**。
> 这些顶点是算出来的，改完一定要和 `genicon -preview` 出的图对一眼。

## 六、托盘图标：另一套配色逻辑

托盘（`app/trayicon.go`）用的是**同一个几何、不同的配色**。

```go
var trayColors = map[string]icon.RGB{
	"connected": icon.StateConnected,   // #10B981 薄荷绿
	"starting":  icon.StateStarting,    // #F59E0B 琥珀
	"stopped":   icon.StateStopped,     // #94A3B8 灰
	"failed":    icon.StateFailed,      // #EF4444 红
}
```

生成时调 `icon.ICOFor(icon.StateScheme(c), 16, 32)` —— 给 16 和 32 两个尺寸，
因为**高分屏下 Windows 会取 32px 那张**。

### 为什么托盘要"反色"

看 `icon.go` 的 `StateScheme()`（L48–58）：

```go
return Scheme{
	TileTop:    white,                    // 底板 → 白
	TileBottom: white,
	WarmTop:    mix(base, white, 0.16),   // 右上半块 → 状态色（略亮）
	WarmBottom: base,                     //            状态色
	CoolTop:    base,                     // 左下半块 → 状态色
	CoolBottom: scale(base, 0.78),        //            状态色（略暗）
}
```

**和品牌配色正好对调**：品牌配色是"深色底板 + 彩色的两半"，
托盘配色是"**状态色铺满 + 一道白斜线**"。

原因写在源码注释里：托盘只有 **16px**，而斜分图形几乎铺满整个方块。
如果照搬品牌配色，状态色就只剩一条细线，根本看不见。
对调之后是"一个状态色方块 + 一道白斜线"，**一眼就能分辨状态**。

> 💡 想改托盘的状态色，改 `icon.go` L61–66 那四个 `State*` 变量，
> 不要去动 `trayicon.go` 的映射表结构。

## 八、exe 文件属性（`wails.json` 的 `info` 段）

右键 `CikPier.exe` → 属性 → 详细信息，里面显示的"产品名称 / 公司 / 版权"
来自两处配置的配合：

**`app/wails.json` 的 `info` 段** —— 填**值**：

```json
"info": {
  "companyName": "Cikian",
  "productName": "CikPier",
  "productVersion": "1.0.0",
  "copyright": "Copyright © 2026 Cikian",
  "comments": "frp 客户端图形界面"
}
```

**`app/build/windows/info.json`** —— 决定这些值**写进 exe 的哪个语言块**：

```json
{
  "fixed": {
    "file_version":   "{{.Info.ProductVersion}}",
    "product_version": "{{.Info.ProductVersion}}"
  },
  "info": {
    "0409": {
      "FileVersion":     "{{.Info.ProductVersion}}",
      "ProductVersion":  "{{.Info.ProductVersion}}",
      "CompanyName":     "{{.Info.CompanyName}}",
      "FileDescription": "{{.Info.ProductName}}",
      "InternalName":    "{{.Info.ProductName}}",
      "LegalCopyright":  "{{.Info.Copyright}}",
      "ProductName":     "{{.Info.ProductName}}",
      "Comments":        "{{.Info.Comments}}"
    }
  }
}
```

链路：`wails.json` 的 `info` → Wails 渲染 `build/windows/info.json` 的模板占位符 →
用 `tc-hib/winres` 生成一个 `<name>-res.syso` → **编译前**放进项目根 → `go build` 链进 exe →
编译完 Wails 自动删掉那个 syso。

### ⚠ 两个必须注意的坑（都踩过）

**坑 1：`"info"` 下面的键必须是具体语言 ID，不能是 `"0000"`。**

Wails 用 `wails init` 生成的默认模板写的是 **`"0000"`**（语言中立）。
那个键会被 `winres` 解析成语言 ID `0x0000`，而 Windows 的资源管理器和
`FileVersionInfo` 是**按具体语言**（例如 `040904B0`）去查字符串表的 ——
结果就是**资源明明存在，属性页却一片空白**。

所以改成 `"0409"`（英语 - 美国）。键名按 `%X` 解析成 `uint16`，也可以写 `"0804"`（简体中文），
但 `0409` 是各种读取工具默认会找的那个，**用它最稳**。

> 判断资源到底在不在（而不是被读不到）的办法：解析 PE 资源目录看有没有
> `RT_VERSION`（type 16）。本项目实测 `CikPier.exe` **有**这个资源，
> 内容也完全正确，纯粹是语言块选错导致读不出来。

**坑 2：字符串表里必须有 `FileVersion` 这一项。**

Wails 默认模板只给了 `ProductVersion`，没有 `FileVersion`。
而 Windows 的 `FileVersionInfo.FileVersion`（也就是属性页上的"文件版本"）
**依赖 `FileVersion` 这个字符串项** —— 缺了它那一栏就是空的。

上面那份模板已经把 `FileVersion` 和 `InternalName` 都补上了。

### 不改会怎样

Wails 有个兜底逻辑（`internal/project/project.go` L190–201）：

- `companyName` / `productName` 为空时 **取 `wails.json` 的 `name` 字段**
- `productVersion` 为空时 **硬编码成 `"1.0.0"`**

而 `name` 是给工具链用的**小写标识**（`cikpier`），
于是 exe 属性里就会显示小写的 `cikpier` —— 看着像没做完。

**所以改程序名时这一段一定要跟着改。**

### 怎么验证

```powershell
(Get-Item 'app\build\bin\CikPier.exe').VersionInfo |
  Format-List ProductName, CompanyName, FileDescription, FileVersion, ProductVersion, LegalCopyright
```

期望输出：

```
ProductName     : CikPier
CompanyName     : Cikian
FileDescription : CikPier
FileVersion     : 1.0.0
ProductVersion  : 1.0.0
LegalCopyright  : Copyright © 2026 Cikian
```

**七项全空 = 踩了坑 1；只有 FileVersion 空 = 踩了坑 2。**

## 九、界面主色和图标要协调

| 东西 | 颜色 | 定义在哪 |
|---|---|---|
| 界面主色（按钮/开关） | 薄荷绿 `#10B981` … | `main.css` 的 `--mint-*` |
| 界面状态色 | 绿/琥珀/灰/红 | `main.css` 的 `--ok` `--warn` `--idle` `--danger` |
| **exe 图标** | 藏青 + 琥珀/橙 + 亮蓝/蓝 | `icon.go` 的 `Brand` |
| **托盘状态色** | 和界面状态色一致 | `icon.go` 的 `State*` |

注意：**托盘四色和界面的语义状态色是同一套值**（`#10B981` / `#F59E0B` /
`#94A3B8` / `#EF4444`），但它们是**两份独立的定义**（一份在 CSS，一份在 Go）。

> ⚠ 改界面状态色的话，**记得两边一起改**，否则托盘颜色和界面提示条会对不上。

而 **exe 图标用的是橙+蓝**（来自作者的个人标识），和界面的薄荷绿并不一致 ——
这是当初有意保留的。如果你想让整个产品视觉统一，
按 §四 的「改法 A」把 `Brand` 换成薄荷绿色系即可。
