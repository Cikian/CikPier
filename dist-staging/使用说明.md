# CikPier · 使用说明

CikPier 是一个**图形界面的 frp 客户端**。

它的作用是：把你**本机的服务**（网站、数据库、远程桌面……）发布到公网，
让外面的人能访问到 —— 但完全不用编辑配置文件，也不用打开黑窗口。

**这份文档怎么读**

- 第一次用 → 只看 [第一章](#一第一次使用三步)，五分钟就能跑起来
- 想发布某个具体服务 → 直接跳 [第四章](#四发布你自己的服务)，里面有分场景的填表指引
- 遇到问题 → [第十二章 常见问题](#十二常见问题) + [第十章 连接诊断](#十连接诊断)
- 想搞懂原理 → [第三章](#三先搞懂几个概念)

## 一、第一次使用（三步）

### 第 1 步：确认文件夹里有两个程序

```
CikPier.exe       ← 你双击运行的就是这个
frpc.exe          ← frp 官方主程序，不要删、不要改名
```

> ⚠ 这两个文件必须**放在同一个文件夹里**。少了一个，程序会提示"找不到 frpc.exe"。

建议把这个文件夹放在**不需要管理员权限**的位置（例如 `D:\CikPier\`），
**不要**放在 `C:\Program Files\` —— 那里每次操作都可能弹管理员确认框。

### 第 2 步：先问管理员要三样东西

**这三样东西不在程序里，必须由服务端管理员给你**：

| 要问的 | 长什么样 | 说明 |
|---|---|---|
| **服务器地址** | `frp.example.com` 或 `123.45.67.89` | 服务端的域名或 IP |
| **服务器端口** | 一般是 `7000` | 控制端口。不确定就问，**别猜** |
| **认证令牌 Token** | 一串随机字符 | 相当于密码，必须**一字不差**。<br>**如果管理员说"没有认证/不需要令牌"，就留空** |

> 💡 **关于"没有认证"**：有些服务端不设令牌（`frps.toml` 里没有 `auth.token`）。
> 这种情况下客户端也**什么都不填**，照样能连上 —— 程序允许令牌留空，不会拦你。
> 判断标准只有一条：**管理员给你的令牌是什么就填什么；他说没有，就留空。**
> 拿不准就去问一句，别自己猜。

顺便可以问一下：**有没有给你分配域名、可以用的对外端口范围是多少**。
发布网站和发布数据库需要的东西不一样，见 [第四章](#四发布你自己的服务)。

### 第 3 步：双击 `CikPier.exe`，跟着向导走

第一次打开会自动进入**配置向导**，依次填写：

| 要填的 | 说明 |
|---|---|
| **服务器地址** | 上面问到的 |
| **服务器端口** | 不确定就填 `7000` |
| **认证令牌 Token** | 一字不差。**服务端没有认证时留空**（框里什么都不填） |
| 你的身份标识 | 管理员给你的名字，例如 `zhangsan`。不填也能用 |
| 本机标识 clientID | **只有"同一个身份下有多台电脑"时才需要填**，且每台不能重复 |

填完点「下一步」→「开始使用」。程序会自动生成配置文件并启动 frp。

### 然后看顶栏

窗口最上面那一行显示当前的连接状态：

| 显示 | 含义 | 要做什么 |
|---|---|---|
| 🟢 **已连接到服务端** | 一切正常 | 可以开始发布服务了 |
| 🟡 **正在连接…** | 正在建立连接 | 等几秒；一直不变见 [第十二章](#q一直卡在正在连接) |
| 🔴 **连接失败** | 连不上 | 看提示里的原因，或去「连接诊断」页 |

**顶栏变绿了，才算真的通了。** 没变绿之前，后面的操作都不会生效。

## 三、先搞懂几个概念

跳过这章也能用，但理解了会少走很多弯路。

### 3.1 frp 在做什么

平时家里的电脑和公司内网，外面是**访问不进来**的（没有公网 IP、有防火墙）。

frp 的办法是：找一台**有公网 IP 的服务器**（服务端）做中转。
你的电脑（客户端）主动连上服务器，说"我有服务要发布"，
服务器就把外面的请求转给你。

**关键点：是你的电脑主动往外连**，所以不需要公网 IP，也不需要改路由器。

### 3.2 服务端 和 客户端

| | 是什么 | 谁负责 |
|---|---|---|
| **服务端**（frps） | 有公网 IP 的那台服务器 | **管理员**部署，你管不着 |
| **客户端**（frpc） | 跑在你自己电脑上 | 就是这个程序在管的 |
| **CikPier** | 客户端的图形界面 | 你在用的东西 |

### 3.3 代理 和 访问者

这是 frp 里最容易搞混的两个词：

| 词 | 谁用 | 干什么 |
|---|---|---|
| **代理**（Proxy） | **发布服务的人** | "把**我**的服务发布出去" |
| **访问者**（Visitor） | **访问服务的人** | "我要访问**别人**发布的私密服务" |

**99% 的情况下你只需要「代理」。** 访问者只在一种场景下用得到：
别人发布了一个"私密服务"（STCP / XTCP），而你是被允许访问的那个人。
详见 [第六章](#六访问者访问别人的私密服务进阶)。

### 3.4 两种"对外方式"：端口 vs 域名

frp 发布服务有两种方式，**这决定了你要问管理员要什么东西**：

| 方式 | 长什么样 | 需要什么 | 适用 |
|---|---|---|---|
| **端口** | `服务器地址:20001` | 管理员给你一个**对外端口** | 数据库、远程桌面、SSH、游戏 |
| **域名** | `web.服务端域名` | 管理员给你一个**域名**（并做好泛解析） | 网站、网页后台、API |

在新建代理时选类型就是在选这个 —— 选 `TCP` 就是端口方式，选 `HTTP` 就是域名方式。

## 四、发布你自己的服务

在「代理」页点右上角 **新建代理**。

### 4.1 八种代理类型

弹窗最上面那排按钮就是类型。**每个按钮下面有小字**说明了它的对外方式：

| 类型 | 小字 | 对外方式 | 一句话说明 |
|---|---|---|---|
| **TCP** | 端口 | `服务器地址:端口` | 最通用。数据库、远程桌面、SSH、游戏都行 |
| **UDP** | 端口 | `服务器地址:端口` | 同上，但走 UDP 协议 |
| **HTTP** | 域名 | `子域名.服务端域名` | 发布网站 / 网页后台 / API |
| **HTTPS** | 域名 | `子域名.服务端域名` | 同上，但服务端直接处理 HTTPS |
| **TCPMUX** | 复用 | `服务器地址:端口` | 多个服务共用一个端口，靠协议区分。**需要服务端支持** |
| **STCP** | 私密 | — | 私密 TCP。**只有拿着密钥的人能访问**，不对外暴露 |
| **SUDP** | 私密 | — | 私密 UDP，同上 |
| **XTCP** | P2P | — | 私密 + **点对点直连**，速度最快，但需要双方网络支持 |

> 💡 弹窗里也有一句提示：**发布网站选 HTTP，发布数据库 / 远程桌面选 TCP，
> 只给特定人访问选 STCP。**

### 4.2 怎么选：决策表

| 你要发布什么 | 选 |
|---|---|
| 网站 / 网页后台 / Web API | **HTTP**（服务端没配 HTTPS 时）或 **HTTPS** |
| MySQL / Redis / PostgreSQL | **TCP** |
| 远程桌面 RDP / SSH | **TCP** |
| 游戏服务器 | **UDP**（少数游戏要 TCP，看游戏说明） |
| 只想给自己或几个同事访问，不想暴露到公网 | **STCP** |
| 同上，但追求速度、两边网络条件好 | **XTCP** |
| 公司内网有一堆服务，但只开了一个对外端口 | **TCPMUX** |

> **不确定就选 TCP** —— 它最通用，配置最简单。

### 4.3 第 2 步：填基本信息

| 字段 | 说明 |
|---|---|
| **名称** | 代理的唯一标识。建议**只用字母、数字和连字符**，例如 `mysql`、`web-hr` |
| **对外端口**（仅 TCP / UDP） | 别人访问时用的端口，**由管理员分配**。<br>填 `0` 表示让服务端**随机分配**一个 |
| **子域名**（仅 HTTP / HTTPS） | **只写最左边一段**。例如填 `web`，实际访问地址就是 `web.管理员给你的域名`。<br>**这是推荐方式** —— 服务端已经配好泛解析，你不用碰 DNS |
| **自定义域名**（HTTP / HTTPS / TCPMUX） | **一般不需要填**，它在界面里默认是收起的。<br>只有你**有自己的域名**、想让服务被它访问时才填；填了要**自己配 DNS**，见下方说明 |
| **多路复用器**（仅 TCPMUX） | 目前仅支持 `httpconnect`。**需要服务端开启 `tcpmuxHTTPConnectPort`**，否则这条代理无法启动 |

#### 关于「自定义域名」——什么情况下才用它

**默认不用管它。** 用上面的「子域名」就够了：服务端配好了泛解析，你只要填一段名字。

只有一种情况需要用它：**你有自己的域名**（比如 `你的域名.com`），想让服务通过
`db.你的域名.com` 这样的地址访问，而不是服务端分配的 `子域名.服务端域名`。

**填了之后你必须做两件事，否则外面访问不到：**

1. 在**你的域名服务商**那里加一条解析 —— **A 记录**指向服务端 IP，或 **CNAME** 指向服务端域名
2. 确认服务端的 **80 / 443** 端口能从外网访问到

> ⚠ **不能填"服务端泛解析域名"下面的域名。** 比如管理员给你的泛解析是
> `frp.example.com`，那你就不能填 `a.frp.example.com` —— 服务端会拒绝这条代理。

> 💡 **它和「子域名」不冲突**，两个都填也可以：frp 会把两个域名都指向这条代理。

> 💡 **TCPMUX 类型例外**：它没有「子域名」这一项，所以自定义域名是**必填**的，
> 界面上会自动帮你展开，并标注「TCPMUX 必填」。

> ⚠ **「对外端口」和「子域名」都别自己乱填。** 这些资源在服务端是**共享**的 ——
> 你占了别人要用的端口或子域名，对方的服务就起不来了。
> **一定要问管理员要。**

### 4.4 第 3 步：填本机端口

「本机地址」默认 `127.0.0.1`（本机回环），一般不用改。
「本机端口」填**你电脑上那个服务真正在用的端口**：

| 你的服务 | 常见本机端口 |
|---|---|
| MySQL | 3306 |
| Redis | 6379 |
| PostgreSQL | 5432 |
| 网站（nginx / IIS / Apache） | 80 |
| 远程桌面 RDP | 3389 |
| SSH | 22 |

> 💡 填本机端口时，程序会**顺手检查一下这个端口有没有服务在监听**。
> 如果提示"没有服务在监听"，先把你自己的服务启动起来再回来 ——
> 否则发布出去也没人能访问。

> 💡 **「后端方式」** 除了默认的"本机端口"，还有"插件模式"。
> 插件模式下不需要填本机端口，由 frp 自带插件处理连接
> （例如把本地 HTTP 转成 HTTPS、或直接提供静态文件服务）。
> 用不到就别动它。

### 4.5 高级选项逐项说明

往下滚是高级选项。**大多数情况全部留默认就行**，这里逐项解释一下：

| 选项 | 默认 | 说明 |
|---|---|---|
| **HTTP 用户名 / 密码** | 空 | 给 HTTP 类型加一层基础认证（浏览器会弹登录框） |
| **按 HTTP 用户路由** | 空 | 按 HTTP Basic Auth 的用户名把请求分给不同后端 |
| **仅转发这些路径** | 空 | 只转发指定路径的请求，其余返回 404 |
| **改写 Host 头** | 空 | 转发时替换 Host 头（后端做虚拟主机时用） |
| **限速** | 空 | 限制这条代理的带宽上限，单位可用 KB / MB |
| **负载均衡组** | 空 | 同一组的多个代理之间分摊流量 |
| **加密**（开关） | 关 | 对这条代理的流量**额外加密**，会略微增加延迟 |
| **压缩**（开关） | 关 | 适合**文本类**流量，会占用更多 CPU |
| **健康检查**（开关） | 关 | **后端不可用时停止发布**。⚠ 见下方警告 |
| ├ 检查间隔 / 超时 / 检查路径 | — | 健康检查开关打开后才需要填 |
| **NAT 打洞**（仅 XTCP） | 关 | 只用 STUN 发现的公网地址，不使用本地网卡地址（VPN 环境下可提升性能） |

> ⚠ **开「健康检查」前先读这句**：打开之后，**必须先把你的本机服务启动起来**，
> 否则这条代理**永远不会上线**（frp 在健康检查通过之前不发布它）。
>
> 而且这个状态**不会报错**，只在日志里刷 `do one health check failed`。
> 所以你会看到"代理建好了但一直是灰色的"。
>
> 如果你不需要这个行为，**关掉健康检查**。

### 4.6 第 4 步：保存并验证

点「**保存并应用**」。列表里这条代理会变成 🟢 **运行中**。

**看到 🟢 之后，一定要自己真的连一次**：

| 类型 | 怎么验证 |
|---|---|
| TCP | 用 `服务器地址:对外端口` 连一下（例如 MySQL 客户端、远程桌面） |
| HTTP | 浏览器打开 `http://子域名.服务端域名/` |
| STCP / XTCP | 需要先建一个访问者，见 [第六章](#六访问者访问别人的私密服务进阶) |

> 💡 **HTTP 类型的对外地址不显示端口，这是正常的。**
> 见 [常见问题](#q为什么-http-代理的对外地址不显示端口)。

## 五、每条代理都能单独开关

列表最右边有个**绿色开关**：

- **关掉** → 只停这一条，**其它的照常工作**
- **打开** → 重新上线

不需要停掉整个 frp。

| 操作 | 怎么做 |
|---|---|
| 改内容 | 点 ✏️ 图标（会有确认提示） |
| 删掉 | 点 🗑 图标（会有确认提示） |
| 找某一条 | 列表上方可以**搜索** |
| 只看某类 | 列表上方可以**按类型筛选**、**按状态筛选** |

### 状态徽标的含义

| 状态 | 含义 | 要做什么 |
|---|---|---|
| 🟢 运行中 | 已发布，外部可访问 | 正常 |
| ⚪ 已停用 | 你手动关掉了 | 需要时打开开关 |
| 🟡 新建 / 等待 | 刚创建，还没上线 | 等几秒；一直不变见下 |
| 🔴 启动失败 | 有问题 | **鼠标悬停在状态上**能看到中文原因 |

**「启动失败」的常见原因**：

- 对外端口已被别人占用 → 换一个（问管理员）
- 服务端没开对应功能（TCPMUX、子域名）→ 联系管理员
- 健康检查失败 → 见上面的警告

## 六、访问者：访问别人的私密服务（进阶）

> **如果你只是要发布自己的服务，这一章可以跳过。**

### 6.1 什么情况下用得到

有人（比如同事、朋友）用 **STCP / SUDP / XTCP** 发布了一个服务，
**没有暴露到公网**，只允许拿着密钥的人访问。你就是那个被允许的人。

**访问者不会给别人开端口**，它只在你本机开一个端口，把流量转过去。

### 6.2 你要从对方那里拿到四样东西

| 要问对方的 | 对应界面上的字段 |
|---|---|
| 他给你起的**代理名字** | 服务名称 `serverName` |
| **密钥** | 密钥 `Secret Key` |
| 他的**身份标识**（如果设了的话） | 发布者身份 `serverUser` |
| 他用的是 stcp 还是 xtcp | 访问者类型 |

### 6.3 填表

在「访问者」页点 **新建访问者**：

| 字段 | 怎么填 |
|---|---|
| **访问者类型** | `stcp`（私密 TCP，走服务端中转）/ `sudp`（私密 UDP）/ `xtcp`（点对点，速度最快） |
| **名称** | 随便起，例如 `zhangsan-mysql` |
| **发布者身份 `serverUser`** | 对方 `frpc.toml` 里 `user` 的值。**留空表示对方没有设置身份** |
| **服务名称 `serverName`** | **对方那条代理的名字**（是对方起的名字，不是你看到的域名） |
| **密钥 `Secret Key`** | 必须和对方的**完全一致**，否则连不上 |
| **映射到本机地址** | 默认 `127.0.0.1`，一般不用改 |
| **映射到本机端口** | **你自己定**一个本机没被占用的端口，例如 `13306` |

保存并应用之后，**用「映射到本机端口」访问对方的服务**：

```
对方发布：MySQL 服务，服务名 mysql-svc
你填：    映射到本机端口 13306
怎么用：  用 MySQL 客户端连 127.0.0.1:13306
```

### 6.4 注意事项

- **访问者没有"运行中"这个状态。** 界面只显示"已启用 / 已停用" ——
  因为 frp 不提供访问者的运行状态。**不显示运行中不代表它没工作。**
  能不能连通，直接拿客户端去连一下最准。
- **`serverName` 填错是最常见的失败原因**。它必须**一字不差**是对方给代理起的名字。
- 密钥泄露等于服务对泄露者开放。**别把密钥贴到群里。**

## 十二、常见问题

### Q：我的电脑是 ARM 的（骁龙笔记本 / Surface Pro X），该用哪个版本？

看分发包的**文件名**：

| 文件名 | 适用电脑 |
|---|---|
| `CikPier-v1.0.0-amd64.zip` | 普通电脑（Intel / AMD 处理器） |
| `CikPier-v1.0.0-arm64.zip` | ARM 电脑（骁龙处理器、Surface Pro X 等） |

不确定自己是哪种？打开 **设置 → 系统 → 关于**，看「系统类型」那一行：

- 写「基于 x64 的处理器」→ 用带 `-amd64` 的那个
- 写「基于 ARM64 的处理器」→ 用带 `-arm64` 的那个

> ⚠ **拿错了会怎样**：x64 版本在 ARM 电脑上**能启动、也能连上**，看起来一切正常，
> 但 Windows 是靠模拟层跑的，而 frp 用的 WebView2 组件在这个组合下有已知的崩溃问题 ——
> 数据一多就可能卡死或闪退。
>
> 好消息是：**程序会自己发现这件事**。装错了会在「代理」页顶部弹一条黄色提示，
> 直接告诉你该换成哪个版本；「连接诊断」页里也能看到当前是原生运行还是在模拟层里。

### Q：提示"找不到 frpc.exe"

把官方下载的 `frpc.exe` 放到和 `CikPier.exe` **同一个文件夹**，然后重启程序。

> ⚠ 注意：`frpc.exe` 也必须和主程序**同架构**。所以换包时**整个文件夹一起换**，
> 不要只替换其中一个 exe —— 那会导致"界面能开但 frp 起不来"。

### Q：一直卡在"正在连接…"

**先去「连接诊断」页**，它会告诉你是哪一步不通。按可能性排序：

1. 服务器地址或端口填错
2. Token 和服务端的 `auth.token` 不一致
3. 服务器防火墙拦了控制端口
4. **`frpc.toml` 里的 `log.to` 不是 `console`** —— 这种情况界面上会直接给出
   「**修正并重启 frp**」按钮，点一下就好

> 第 4 条的原理：程序是靠读 frp 的输出来判断连接状态的。
> 如果日志被写进文件而不是输出到程序，程序就"看不见"frp 到底连上没有，
> 于是**明明已经连上了，界面却一直显示正在连接**。

### Q：管理员说服务端"没有认证"，令牌要填什么？

**什么都不填，留空就行。**

有些服务端不设令牌（`frps.toml` 里没有 `auth.token`）。这种情况下
客户端也必须留空，两边都是空才能对上 —— 这属于正常用法，不是配置不全。

- 向导里**令牌框留空**就能点「下一步」，程序不会拦你
- 「设置」页里也允许把已有的令牌**清空**
- 「连接诊断」页的「配置」那一行会写明是
  「未设置（服务端未开启认证）」，看到这个不用紧张

> ⚠ **怎么确认服务端到底有没有认证？** 只有两个可靠办法：
> ① 问管理员；② 看服务端的 `frps.toml` 里有没有 `auth.token` 这一行。
> **不要靠猜** —— 填错令牌和留空是两种不同的失败，现象都是连不上，
> 但原因完全不一样。

### Q：为什么 HTTP 代理的「对外地址」不显示端口？

因为 HTTP/HTTPS 类型走的是**域名**：服务器根据你访问的域名把请求转发给你，
你在浏览器里只需要输入 `http://web.你的域名/`，**不需要端口**。

frp 本身报上来的是「域名 + 服务端的内部端口」，那个端口通常由 nginx 之类在前面
做反向代理，而且往往被防火墙挡着 —— **直接加上去反而访问不了**。
所以界面上只显示域名，把端口和解释放在了鼠标悬停的提示里。

> **TCP / UDP 不一样**：它们的对外地址就是 `服务器地址:对外端口`，**端口必须带上**。

### Q：代理状态是"启动失败"

**鼠标悬停在状态上**能看到中文原因。常见的有：

- **对外端口已被别人占用** → 找管理员换一个
- **服务端没开对应功能**（比如 TCPMUX、子域名）→ 联系管理员
- **健康检查失败** → 见下一条

### Q：代理显示"健康检查失败"，但我的服务明明是好的

这条代理开了「健康检查」。frp 在**你的本机服务启动之前不会把它发布出去** ——
所以先把你自己的服务（MySQL / 网站…）启动起来，这条代理会自动上线。

如果你不需要这个行为，可以在代理的「高级选项」里把**健康检查关掉**。

### Q：代理一直是灰色的（"新建"状态），也不报错

两种可能：

1. **开了健康检查，本机服务还没起来** —— 见上一条
2. 就是还没连上服务端 —— 看顶栏是不是 🟢

### Q：提示"检测到本机已有另一个 frp 进程在运行"

管理端口上已经有一个 frpc 在跑，但**不是这个程序启动的** ——
可能是上次异常退出留下的，或者你另外配置了开机启动。

界面上的按钮可以把它停掉，之后就能用本程序正常接管了。

> ⚠ **停之前先确认那个进程确实是你自己的**，别把别的服务的 frp 停掉了。
> 不确定的话去任务管理器看一下命令行。

### Q：提示"读不到 frp 的日志"

说明 `frpc.toml` 里的 `log.to` 指向了文件而不是 `console`。
这种情况程序看不到 frp 的输出，也就无法判断连接状态。

界面上有「**修正并重启 frp**」按钮，点一下就好。

### Q：我手动改了 `frpc.toml`，界面会覆盖吗？

程序只在**你点「保存」的时候**重写这个文件，而且**每次都会先备份**成 `frpc.toml.bak`。

另外注意：**代理不存在这个文件里**，而是存在 `frpc-store.json`。

> 💡 想改回上一次的配置，把 `frpc.toml.bak` 改名为 `frpc.toml` 即可
> （程序要处于退出状态）。

### Q：以前手写的代理在界面里改不了

如果 `frpc.toml` 里有手写的 `[[proxies]]`，界面上会提示有一批**"无法管理的代理"** ——
因为写在配置文件里的代理**不能被单独启停或编辑**（这是 frp 的限制）。

点「**导入到界面管理**」就能把它们搬进界面，**原配置会自动备份**。

### Q：改了「对外端口」或「子域名」之后别人访问不了

大概率是**你填的值和管理员分配的不一致**，或者和别人的冲突了。
这两个资源在服务端是**共享**的，一定要用管理员给你的值。

### Q：能同时发布多个服务吗？

能，**想建多少条代理都行**，每条独立开关、互不影响。

### Q：程序关掉了，我发布的服务还在吗？

**不在了。** 发布服务的通道是由你电脑上的 `frpc.exe` 维持的，
程序退出、电脑关机、休眠，服务就断了。

如果需要长期在线，考虑：
- 让程序**开机自动启动**（设置页）
- 关窗口时选"最小化到托盘"而不是退出
- 用一台长期开机的机器来跑

### Q：怎么知道对方在连我的服务？

「日志」页会显示连接记录。想看更详细的统计，
可以用「设置 → 打开官方管理页面」，里面有 frp 自带的流量统计。

### Q：换了台电脑 / 想搬家怎么办？

见 [第十四章](#十四备份与搬家)。

## 十四、备份与搬家

### 14.1 要备份哪些文件

| 文件 | 内容 |
|---|---|
| `frpc.toml` | 连接配置（服务器地址、端口、Token） |
| `frpc-store.json` | **你的所有代理** |

2. 把上面三个文件**复制到新电脑的程序目录里**，覆盖同名文件
3. 打开程序，检查顶栏是不是 🟢

> ⚠ **如果新电脑和旧电脑要同时在线，必须改一个不同的 `clientID`**
> （设置页里改），否则两台会互相冲突。

### 14.3 拷贝给别人

⚠ **先把 `frpc.toml`、`frpc-store.json`、`gui-settings.json` 删掉再拷。**
留着的话，等于把你的 Token 和代理列表一起送出去了。

  确保自己有足够强的密码，**或者改用 STCP 只给指定的人访问**
- 🔐 **STCP / XTCP 的密钥泄露 = 服务对泄露者开放** —— 别贴群里
- 🖥 **管理页面只监听本机** —— 不要把 `webServer.addr` 改成 `0.0.0.0`，
  那等于把你本机的管理接口暴露到局域网
- 👀 **不确定就先问管理员** —— 大部分问题问一句就解决了，比乱试快

## 附二、常见服务端口对照表

| 服务 | 默认端口 | 协议 | 建议 |
|---|---|---|---|
| MySQL / MariaDB | 3306 | TCP | 强烈建议设强密码，或改用 STCP |
| PostgreSQL | 5432 | TCP | 同上 |
| Redis | 6379 | TCP | **必须设密码**，否则等于开放数据库 |
| MongoDB | 27017 | TCP | 必须开认证 |
| SQL Server | 1433 | TCP | 设强密码 |
| 远程桌面 RDP | 3389 | TCP | ⚠ 暴露到公网风险高，建议用 STCP |
| SSH | 22 | TCP | 建议改用密钥登录、禁用密码 |
| 网站（nginx / IIS / Apache） | 80 / 443 | HTTP | 用 HTTP / HTTPS 类型 |
| VNC | 5900 | TCP | ⚠ 同 RDP，建议 STCP |
| Minecraft | 25565 | TCP/UDP | 用 TCP 或 UDP（看服务端版本） |

> 💡 **上表是"本机端口"该填什么。**
> 「对外端口」是另一回事，**由管理员分配**。
